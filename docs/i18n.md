# Finnish / English interface

Research Evidence Explorer supports **Finnish (default)** and **English** as presentation locales. Canonical research records stay Finnish in the workspace JSON; English is an overlay for UI chrome and curated research display fields.

Term pairs and translation caveats live in [glossary-fi-en.md](glossary-fi-en.md).

## Language selection

| Rule | Behaviour |
| --- | --- |
| Storage key | `research-evidence-explorer-locale-v1` (separate from workspace `research-evidence-explorer-v1`) |
| Stored preference | Wins when present and valid (`fi` \| `en`) |
| Browser detect | First `navigator.languages` / `language` entry that is Finnish or English; otherwise Finnish |
| Default | Finnish |
| Document language | `document.documentElement.lang` is set to the active locale |

Implementation: `src/i18n/locale.ts`, `src/i18n/I18nContext.tsx` (`LanguageSelector`).

## Language switch is presentation-only

Changing language:

- does **not** save or discard research edits
- does **not** append revision / `editLog` events
- does **not** change the scientific **content hash**
- does **not** rewrite workspace JSON or figure `snapshotContentHash`

Figures may record `displayLanguage` and `translationResourceVersion` for provenance; those metadata fields do not alter scientific content identity.

## UI catalogue

- Finnish strings: `uiFi` in `src/i18n/catalog.ts`
- English twin: `uiEn` (same key tree; TypeScript enforces parity via `CatalogTwin`)
- Lookup: `t(locale, key, vars?)` with `{name}` interpolation

**Adding a UI key:** add the leaf under the same path in both `uiFi` and `uiEn`, then use `t('…')` / `useI18n().t`. Run `npm test` (leaf-path parity is covered in `tests/i18n.test.ts`).

## Research English overlay

| Artifact | Role |
| --- | --- |
| `data/i18n/research-en.json` | Translations keyed by collection → record id → field |
| `data/i18n/research-manifest.json` | `sourceContentHash`, `resourceVersion`, review date |

`translateResearchField` / `displayRecordLabel` (`src/i18n/research.ts`):

- **fi** → original Finnish text
- **en** + translation present + hash matches → English text
- **en** + missing translation → original + missing-translation notice
- **en** + hash mismatch → English text kept with **needs review** notice

Update the overlay when curated Finnish scientific text changes: edit `research-en.json`, then set `sourceContentHash` in the manifest to the current `contentHash(workspace)` (scientific content only). Bump `resourceVersion` when the translation set is reviewed.

**Adding a research translation:** under the matching collection and id in `research-en.json`, add the field key (e.g. `label`, `definition`, or protocol `dim.*.label` / `anchor.*.wording`). Prefer glossary wording. Do not invent stronger claims than the Finnish source.

## Presentation exports vs canonical JSON

| Export | Language |
| --- | --- |
| Workspace / snapshot JSON | Canonical Finnish scientific fields (plus layout, log, hashes) |
| Quick SVG / reproducible figures | May localise labels and legend via `locale`; manifest records `displayLanguage` |
| UI chrome / dialogs | Active locale from the catalogue |

Canonical JSON remains the source of truth for content hashing and import/export round-trips.

## Untranslated by design

These stay in the original / canonical form even when the UI is English:

- Source claims and imported claim statements (unless a curated overlay entry exists — claims are generally not overlaid)
- Long excerpts and Finnish query variants
- Bibliographic citations, author names, and locator strings tied to sources
- Raw identifiers and machine enums (`epistemicStatus` codes, schema fields)

Empty matrix cells still mean “not recorded”, not a proven research gap, in both languages.
