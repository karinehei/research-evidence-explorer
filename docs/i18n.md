# Finnish / English interface

Research Evidence Explorer supports **Finnish (default)** and **English** as presentation locales. Canonical research records stay Finnish in the workspace JSON; English is an overlay for UI chrome and curated research display fields.

Term pairs and translation caveats live in [glossary-fi-en.md](glossary-fi-en.md).

## Language selection

| Rule | Behaviour |
| --- | --- |
| Storage key | `research-evidence-explorer-locale-v1` (separate from workspace `research-evidence-explorer-v1`) |
| Stored preference | Wins when present and valid (`fi` \| `en`) |
| Browser detect | First `navigator.languages` / `language` entry that is Finnish or English; otherwise Finnish |
| Default | Finnish |
| Document language | `document.documentElement.lang` is set to the active locale |

Implementation: `src/i18n/locale.ts`, `src/i18n/I18nContext.tsx` (`LanguageSelector`).

## Language switch is presentation-only

Changing language:

- does **not** save or discard research edits
- does **not** append revision / `editLog` events
- does **not** change the scientific **content hash**
- does **not** rewrite workspace JSON or figure `snapshotContentHash`

Figures may record `displayLanguage` and `translationResourceVersion` for provenance; those metadata fields do not alter scientific content identity.

## UI catalogue

- Finnish strings: `uiFi` in `src/i18n/catalog.ts`
- English twin: `uiEn` (same key tree; TypeScript enforces parity via `CatalogTwin`)
- Lookup: `t(locale, key, vars?)` with `{name}` interpolation

**Adding a UI key:** add the leaf under the same path in both `uiFi` and `uiEn`, then use `t('…')` / `useI18n().t`. Run `npm test` (leaf-path parity is covered in `tests/i18n.test.ts`).

## Research English overlay

| Artifact | Role |
| --- | --- |
| `data/i18n/research-en.json` | Translations keyed by collection → record id → field |
| `data/i18n/research-manifest.json` | `sourceContentHash`, `resourceVersion`, review date |

`translateResearchField` / `caseField` / `displayRecordLabel` (`src/i18n/research.ts`):

- **fi** → original Finnish text
- **en** + translation present + hash matches → English text
- **en** + missing translation → original + `research.missingTranslationFi` notice (Finnish original remains visible)
- **en** + hash mismatch → English text kept with **needs review** notice

Update the overlay when curated Finnish scientific text changes: edit `research-en.json`, then set `sourceContentHash` in the manifest to the current `contentHash(workspace)` (scientific content only). Bump `resourceVersion` when the translation set is reviewed. Keep `TRANSLATION_RESOURCE_VERSION` in `src/i18n/locale.ts` aligned with the manifest when figures record that metadata.

**Adding a research translation:** under the matching collection and id in `research-en.json`, add the field key (e.g. `label`, `definition`, protocol `dim.*.label` / `anchor.*.wording`, or nested case keys such as `facet.{id}.label`, `answer.{id}.text`, `passage.{id}.text`, `column.0`, `row.{r}.{c}`). Prefer glossary wording. Do not invent stronger claims than the Finnish source.

### Nested case field keys

Under each case id (`A` / `B` / `C`), curated overlay fields include top-level `title`, `task`, `taskStatement`, `interpretation`, `boundary`, plus:

- `task.essentialQualifications`, `task.temporalScope`
- `facet.{facetId}.label`, `facet.{facetId}.reason`
- `answer.{id}.label`, `answer.{id}.text`, `answer.{id}.note`
- `passage.{id}.text` (locator stays untranslated). Constructed analytical passage texts are translated and remain constructed examples, not empirical excerpts. If a passage were a real Finnish query variant or real excerpt, omit `passage.*.text` so the original shows with fallback.
- `display.{id}.label`, `display.{id}.note`
- `context.{id}.label` (and `note` when present)
- `claimAnn.{id}.label`, `claimAnn.{id}.statement`, `claimAnn.{id}.reason`
- `snap.{id}.label`, `snap.{id}.note`
- `column.{index}`, `row.{r}.{c}`

Edit mode always binds to canonical Finnish values; English is display-only. When locale is English and a translation exists, passages and claim-annotation statements offer a lightweight “Show original Finnish” disclosure.

### Claims

The `claims` collection overlays imported summary `statement` and `limitations` (and `methodContext` when non-empty). Wording must preserve that these are imported summaries, not independent full-text inspections.

## Coverage status

| Layer | Status |
| --- | --- |
| **Complete interface translations** | UI catalogue (`uiFi` / `uiEn`): navigation, matrix, cases chrome, **source/claim inspector forms**, figures, history, snapshot dialog chrome, dialogs |
| **Complete curated-content overlay** | Constructs, criteria, propositions, protocols (including dimension/anchor wording), decisions, relationships, **claims** (`statement` / `limitations`), **cases A–C including nested** task/facet/answer/passage/display/context/claimAnn/snap/column/row fields listed above |
| **Intentionally preserved (FI / canonical even in EN)** | Citations, authors, titles, DOIs, bibliographic strings, machine IDs and enums, locators, `basis` planning-document names, personal notes / new imports without an overlay entry, real Finnish query variants if ever present (omit passage overlay) |
| **Missing / outdated** | Manifest `sourceContentHash` ≠ current scientific `contentHash(research.json)` → show English with **needs review**; missing overlay field → Finnish original + missing-translation notice |

Do **not** claim cases are fully translated if only top-level title/task/interpretation/boundary exist — nested fields are required for complete case coverage.

## Presentation exports vs canonical JSON

| Export | Language |
| --- | --- |
| Workspace / snapshot JSON | Canonical Finnish scientific fields (plus layout, log, hashes) |
| Quick SVG / reproducible figures | May localise labels and legend via `locale`; manifest records `displayLanguage` |
| UI chrome / dialogs | Active locale from the catalogue |

Canonical JSON remains the source of truth for content hashing and import/export round-trips.
